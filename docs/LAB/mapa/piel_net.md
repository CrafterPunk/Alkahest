## Resumen

ROCK SKIN (Assets/Alkahest/Game/PielDeRoca.cs, 901 lines). PielDeRoca is a purely visual, host-and-guest MonoBehaviour: a marching-squares contour mesh drawn per 16x16 chunk under the sim quad (sortingOrder -6) that replaces the sim texture's rendering of MaterialId.Stone ONLY. It asks SimRenderer to skip Stone texels via the static SimRenderer.OcultarRoca (Sim/SimRenderer.cs:275, honored at :1145 `if (OcultarRoca && matId == MaterialId.Stone) return default;`). The scalar field is the mean solidity of the 4 cells around each corner; EsRoca(x,y) (PielDeRoca.cs:447-451) returns true ONLY for `mat == MaterialId.Stone` (out-of-bounds counts as rock). Other StaticSolid materials do NOT get the skin: they only participate as a "junta" (joint) flag that thins the ink line and suppresses bands/decoration where the contour touches another StaticSolid (:311, :585-591, :620, :637, :670). Chunk dirtiness is tracked with two FNV-1a 64-bit hashes per chunk: _hash (HashChunk :298-316, value 2 for Stone, 1 for any other non-Empty StaticSolid, 0 else) recomputed whenever CellGrid.chunkTouchedTick[ci] changes (:192-200) plus a slow round of 24 chunks/frame (:203-208, full pass every ~36 frames, needed because a guest's mirror writes mat[] without touching ticks per :201); and _hashOrilla (HashOrillaChunk :324-350, value 1+matId for Liquid cells 4-adjacent to Stone) checked ONLY in the slow round so a flowing pool doesn't rebuild meshes every tick (:98-105). A hash change dirties the chunk and its 8 neighbours (:286-296); up to 32 dirty chunks are rebuilt per frame (:109, :209-217). Build cost per chunk: 17x17 corner field, a Manhattan distance transform over a 28x28 window (RadioMasa=6, :66,:117,:738-761), polygon emission for 4 mesh layers (sombra/relleno/bandas/deco, z-ordered 0.03..0, :845-879). Levels 0-4 via F7 (PlayerPrefs "PielDeRoca.Nivel", :41-45,:174-185). The R129 MENISCO draws a lightened liquid-coloured strip astride the ink line wherever the cell half a cell outside a contour segment is a Liquid archetype (:640-660, colour = lerp(baseColor, white, 0.55), alpha 0.90). Hooks: static Instancia (:44), Asegurar(sim, atril) (:122-131, created once by ApprenticeController.cs:1215 for the local player only), CargarTexturaDeRoca(Texture2D) (:415-424, hot-load used by GaleriaCurador.cs:205-216 with Galeria/roca_superficie.png + R). Ctrl+Shift+F7 carves a sample cave with _sim.PaintRect/Paint (host only, Stepper==null guard :228-267). To give a NEW static natural material (compacted sediment, hardened clay, caliche) the skin, you must change EsRoca (:450), the "hay" scan (:481), celdaRoca (:511), the junta test (:589), OcultarRoca handling in SimRenderer.cs:1145, HashChunk's value mapping (:311), HashOrillaChunk's Stone adjacency (:340-343), and GenerarTexturaRoca which reads only Stone's baseColor (:886) — none of these are data-driven today; the natural seam is a predicate `EsPiel(byte m)` replacing the 8 literal Stone comparisons.

NETWORKING (Assets/Alkahest/Net/SimSync.cs, 1147 lines). Sim-only-host architecture: the host runs SimStepper; the guest runs a MIRROR (AlkahestSim.ModoEspejo, AlkahestSim.cs:93; Stepper == null) with the same CellGrid + SimRenderer, built with the host's seed via CrearMundoEspejo (AlkahestSim.cs:144) on the first snapshot (SimSync.cs:932-996). ONLY CellGrid.mat[] is replicated (SimSync.cs:50-57, AlkahestSim.cs:423-427). temp[], aux[], morph[], patina[], ambient[] are NOT sent: the guest's temp stays at AmbientRaw (no incandescence), morph is frozen at its SetCell seed (no MorphTick on the mirror), patina is recomputed locally by SimRenderer from the replicated mat (CellGrid.cs:155-159 "cero bytes de tráfico"). Delta mechanism: each chunk is dirty when CellGrid.chunkTouchedTick[ci] != _ultimoTickEnviado[ci] (SimSync.cs:170-171, :708); the host runs two passes (:584-659): PASS 1 every TicksPorDifusionPrioridad=2 ticks (~15 Hz, :115) for dirty chunks whose centre is within RadioPrioridadCeldas=60 cells of ANY avatar (AprendizNet.Todos, :544, :669-694); PASS 2 every TicksPorDifusion=6 ticks (~5 Hz, :91) as a circular sweep from _cursorBarrido; both share MaxChunksPorDifusion=96 (:126). Chunk encoding (:778-823): ushort chunkIndex, ushort nPairs, then (byte mat, byte count<=255) pairs row-major over the 16x16 chunk; worst case 4+512 bytes (:135), a solid chunk is 6 bytes (:729). Messages are CustomMessagingManager named message "AlkChunks" (:86) with header byte tipo (0 delta/1 snapshot) + int seed + ushort nChunks (:147-150), payload cap MaxBytesCarga=16 KB (:144), delivery ReliableFragmentedSequenced (:892-899), sent to all clients except the host (:835-854). Snapshot is requested by the client via SolicitarSnapshotServerRpc (:1140-1145), retried every 2 s while Grid==null (:476-487), and streams all 864 chunks in as many 16 KB messages as needed (:731-770). Client apply: AlkahestSim.AplicarChunkRemoto (AlkahestSim.cs:429-473) writes via CellGrid.SetCell (resets aux to 0 and reseeds morph) only where mat differs, then WakeChunkIndex(cx,cy,TickEspejo) for that chunk only; seed mismatch is a LogError and the message is dropped (SimSync.cs:997-1003). Guest mutations: AlkahestSim.Paint/PaintStable/PaintCell/PaintRect apply locally as prediction AND enqueue an 8-byte record (ushort x, ushort y, byte radio, byte mat, byte modo, byte tempRaw; :154-164, :1040-1065) flushed once per LateUpdate as a byte[] RPC SolicitarPinturaServerRpc (:1097-1130, max 192 records/lote :158). Host applies them but discards the guest's tempRaw — everything a guest pours is born at stable temperature (:1111-1128). AlkahestSim.InyectarTemperatura is NOT forwarded in mirror mode (AlkahestSim.cs:763-778). What a guest cannot do: carve (Cincel disabled, AprendizNet.cs:211-235; Mudanza.cs:554; PielDeRoca sample cave), run any sim/machine/plate logic, see temperature (Termometro shows "—" when Stepper==null, Termometro.cs:341), witness laws (SimStepper.Events host-only, SaberSync.cs:27-28). Machines are replicated as a server-written NetworkList<EntradaMaquina> (MaquinaSync.cs:275-277: tipo, indice, anclaX/Y, centroX/Y, tamanoX/Y, estadoVivo byte) polled at 0.5 s (position) and 0.25 s (estadoVivo) with RPCs for move/use requests validated server-side. Measured/estimated numbers in comments: "90% of the image for 30% of the bandwidth" (SimSync.cs:55), "~155 KB/s por cliente peor caso realista" (docs/archivo/HISTORIAL_RONDAS.md:2946), original estimate 5-30 KB/s at 10-15 Hz (HISTORIAL_RONDAS.md:86), ~200 ms visual lag at 5 Hz reduced to ~66 ms cadence in the priority zone (SimSync.cs:101-107). No runtime bandwidth logging exists in SimSync (only a snapshot message-count log at :768).

## Riesgos

- The skin is hard-wired to MaterialId.Stone in 8 places (PielDeRoca.cs:311,340-343,450,481,511,589,886 and SimRenderer.cs:1145). A new 'caliche/compacted sediment' StaticSolid will render as a flat sim texel with a thin joint line against the contour, not as skinned rock; adding it requires touching all sites consistently or the hash and the mesh will disagree (chunks never rebuilt or rebuilt wrongly).
- Sediment that deposits and hardens next to Stone will thrash PielDeRoca: any change in a StaticSolid cell changes HashChunk (value 1) and rebuilds the chunk + 8 neighbours (up to 32 builds/frame, each with a 28x28 distance transform and 4 mesh uploads). A continuously depositing channel would keep ~9 chunks rebuilding permanently.
- The orilla/meniscus hash includes the liquid's material id (PielDeRoca.cs:344): turbid water that changes id (e.g., clear<->turbid variants) at a bank will trigger rebuilds every slow round (~1 s). A flowing stream far from Stone does not, by design.
- Guest mirror has NO temp/aux/morph/ambient: any new per-cell field (humidity, flow, sediment load, heat) is invisible to guests unless added as a second RLE block per chunk in CodificarChunk/AplicarChunkRemoto (the docblock at SimSync.cs:55-57 reserves this path) — and the header format (byte tipo + int seed + ushort n) has no version field, so both peers must be rebuilt together.
- Bandwidth scaling: the delta is keyed on chunkTouchedTick, and WakeChunk dirties 3x3 (SimSync.cs:119-121). A permanent stream + fire + steam keeps many chunks awake forever, so the 96-chunk/16 KB budget will be hit constantly; MaxChunksPorDifusion caps the burst but the circular sweep then lags. Adding temp doubles worst-case bytes per chunk (516 -> ~1028).
- Determinism hazard: the mirror is NOT a simulation; it never runs SimStepper, so any laboratory 'parameter panel / time scaling / presets' must be host-only and results only reach guests through mat[] deltas. Time scaling (multiple Step() per frame) multiplies the number of dirty chunks per difusión and hence bandwidth.
- Guest paints are forwarded with their temperature discarded (SimSync.cs:1111-1128) and InyectarTemperatura is never forwarded (AlkahestSim.cs:763-770): a guest cannot light the permanent fire, heat water, or cool steam — all thermal actions must be host-side or require a new RPC.
- Latent bug SimSync.cs:1126: ModoPaintRect on the host calls PaintRect(x, y, radio, CellGrid.AmbientRaw, material) — height is replaced by 70 (the tempRaw byte carries the packed height per AlkahestSim.cs:736-737). Any guest tool that uses PaintRect (e.g., a carving/preset tool in the lab) will paint 70-cell-tall rectangles on the host.
- PielDeRoca relies on the slow 24-chunk/frame rehash to see guest-side mat[] writes (comment :201) — on a guest the skin can lag up to ~36 frames behind the mirror, and step 2 only fires when chunkTouchedTick changes (AplicarChunkRemoto does WakeChunkIndex so it usually does).
- Static flags AlkahestGameBootstrap.ModoSemillaCero/ModoFundacion/ModoGaleria are reset on both host spawn and the guest's first snapshot and on despawn (SimSync.cs:355,447-448,973,992): a new 'ModoLaboratorio' flag must follow the same three reset paths ('regla 59') or it leaks between sessions; the guest currently has no way to learn a lab mode except by seed value (only SemillaCero is recognised, :973).
- SimRenderer.OcultarRoca is a global static toggled by PielDeRoca.AplicarModo; PielDeRoca.OnDestroy resets it (:137) — a lab scene that destroys/re-creates the skin must repaint all chunks (MarcarTodoSucio) or Stone texels stay hidden.
- The mirror's SetCell resets aux to 0 on every replicated change (CellGrid.cs:213): any guest-side visual that reads aux (gas life, flow memory) will see zeros; new visuals for turbidity/flow must live in mat ids or a new replicated channel.
- Guests cannot carve (Cincel disabled AprendizNet.cs:233, Mudanza.cs:554 gate), so 'player carves terrain' in a shared lab is host-only unless a new server RPC is added; the existing paint RPC lacks authorisation/validation beyond bounds clamping.

## Oportunidades

- Chunk dirtiness infrastructure is shared by renderer, network and skin (CellGrid.chunkTouchedTick + per-consumer last-seen copies): a new per-cell field only needs to call WakeChunk/WakeChunkIndex to be picked up by all three (SimRenderer.cs:262-270, SimSync.cs:170, PielDeRoca.cs:192-200).
- SimSync's message format is documented as extensible with 'a second RLE block per chunk' for temp (SimSync.cs:55-57); CodificarChunk/AplicarChunkRemoto are small static/instance functions (:778-823, AlkahestSim.cs:429-473) where a quantised temp/humidity block could be appended without changing transport.
- The priority-by-avatar pass (SimSync.cs:669-694) can be reused to send higher-fidelity data (temp, flow) only near players, keeping the 96-chunk budget.
- PielDeRoca's two-hash scheme (silhouette hash vs. slow orilla hash) is a ready template for a deposition skin: a third hash keyed on the new solid could rebuild only on settle/harden events instead of every liquid movement.
- PielDeRoca.CargarTexturaDeRoca + GaleriaCurador hot-load (R key, Galeria/roca_superficie.png) already provides an art-iteration loop for the lab's rock surface without recompiling.
- The junta mechanism (PielDeRoca.cs:585-591, 620, 637, 670) already visually distinguishes Stone from other StaticSolids at the contact line — hardened sediment/caliche would automatically read as 'other solid mortared to rock' with zero code changes.
- MENISCO (PielDeRoca.cs:640-660) already colours the bank strip from the liquid's baseColor — turbid vs clear water variants will show different meniscus tints for free (at ~1 s latency).
- Sample cave carver (PielDeRoca.cs:228-267) shows the host-side carving recipe (PaintRect Stone block, oval Empty, floor, stairs, pillars, ledge, pebble, pool, tunnel) reusable as a lab preset generator; GaleriaCurador.cs shows machine placement via IMovible.Reposicionar + cell snapshot/restore (:218-226).
- AlkahestSim.StepOnce (AlkahestSim.cs:795) and the FixedDt accumulator with MaxStepsPerFrame (:342-356) are the natural hooks for time scaling / single-step in a parameter panel; host-only.
- MaquinaSync's estadoVivo bits + AlCambiarEstadoMaquina event (MaquinaSync.cs:223,258) is the existing pattern for replicating a small 'live state' of a fixed object (a permanent fire/brazier could be a TipoMaquina with FuegoEncendido bit) without touching the cell delta.
- CellGrid.ambient (CellGrid.cs:116) is an existing, unused per-cell climate array intended for player-made local climate (a sealed cold room, a forge) — directly relevant to steam condensation by cooling.
- CellGrid.patina (renderer-only, locally recomputed on every client, CellGrid.cs:155-170) demonstrates how a derived per-cell visual field (wetness/soot) can exist with zero network cost — humidity/turbidity visuals could follow the same 'derive from replicated mat' approach.
- Termometro.cs:341 and DirectorDeAudio (HISTORIAL_RONDAS.md:2935-2940) show the accepted guest-side pattern: gate on Stepper == null and derive from the replicated grid within the camera window.

## Preguntas abiertas

- Should a new hardened-sediment material get the full marching-squares skin (requires widening EsRoca and 7 other Stone literals plus SimRenderer.OcultarRoca) or only the 'junta' treatment it already gets for free? If skinned, does its deposition rate make the per-chunk rebuild cost (32 builds/frame cap) acceptable?
- Will the laboratory be host-only (single-player scene, no SimSync in scene) or a MULTI scene? If MULTI, the guest can't carve, heat, or cool; is a new authorised RPC for carving/thermal tools in scope?
- Is the temp[] second RLE block (documented but never implemented) wanted now? At 15 Hz priority cadence, adding temp roughly doubles worst-case chunk bytes; is a quantised 4-bit or per-4th-tick scheme (HISTORIAL_RONDAS.md:86) acceptable?
- The SimSync.cs:1126 PaintRect height bug: should it be fixed (pass tempRaw as height) before any guest tool uses PaintRect?
- How will the lab's ModoLaboratorio flag reach guests? Today only the seed value is inspected on the first snapshot (SimSync.cs:973); a new mode needs either a reserved seed or an extra header field (which changes the wire format).
- Is there any runtime bandwidth measurement wanted? No counters exist in SimSync (only a snapshot message count log at :768); the ~155 KB/s figure is an analytic worst case from HISTORIAL_RONDAS.md:2946, not measured.
- With time scaling (multiple Step() per frame), does the 96-chunk/16 KB-per-difusión budget need to scale, or should the network cadence stay tied to wall-clock instead of sim ticks (today it's tick-based: SimSync.cs:494-495)?
- Does the skin need to know about sim-paused/single-step (StepOnce) states? Today it rehashes on tick change and in the slow round regardless of pause.
